# NIUBI Skill

## 你不是缺生产力，你是忘了赚钱。

项目做着做着，最容易沉浸在功能、内容和AI生产力里，把收费验证推迟到“再完善一点”。

**NIUBI Skill是项目的赚钱纠偏器。**

在你继续开发、继续发内容或继续投入之前，它先判断你正在做的事情是否真的接近收入，再找出一个离真实收钱最近的赚钱点。

> **少做一点，先拿到一次真实商业反馈。**

```bash
npx -y skills add nathanskill/niubiskill -g --all
```

> 唯一官方来源：`nathanskill/niubiskill`。任何其他 owner 下的同名包都不是官方版本。

## 它只做两件事

### 1. 提醒你：该赚钱了

做产品容易获得完成感，报价、收费和面对拒绝更难，所以人会本能地继续生产。

当一项开发、内容或投入确实挤占了更强的商业动作时，NIUBI Skill会叫停它。你当前的动作本来就对，它会直接肯定并收窄，不为了凑纠偏格式硬造一件该停的事。真实买方提出的成交阻塞，修复后能立即推进承诺或付款的，属于该做的生产。

### 2. 给出最可行的获利路径

后台从不同价值捕获逻辑里比较若干候选，证据足够区分时收敛到一个：

```text
谁付钱 → 为什么付 → 买什么 → 什么事件产生收入
```

它不把模式清单扔给你，而是按照：

```text
权限可做 → 已有买方证据 → 离收钱近 → 七天可验证 → 能交付且经济性可能成立
```

选出一个本周动作、一份可以直接使用的材料和一个七天证据。

[查看获利模式候选库](skills/niubiskill/references/monetization-patterns.md)

## 什么时候必须跑一次

- 准备继续开发新功能、再做一个AI工具；
- 准备重做网站、页面、品牌或内容计划；
- 准备招人、自动化或追加投入；
- 有用户、粉丝、Star或流量，却没有收入；
- 已经有人咨询，却没有报价、承诺或付款；
- 团队一直很忙，但说不清谁会为什么付钱。

## 3步，找到离钱最近的赚钱点

### 1. 安装

```bash
npx -y skills add nathanskill/niubiskill -g --all
```

安装或更新后重新打开Agent。

### 2. 把项目丢进去

```text
$niubiskill https://你的项目网址
告诉我本周先停什么，再找一个离真实收钱最近的赚钱点。
```

没有网址，一句话也行：

```text
$niubiskill
我在做【项目】，现在有【用户、流量、询问或收入】，下一步原本准备【继续做什么】。帮我纠偏并找赚钱点。
```

你只需要描述项目。获利模式、断点定位、证据强弱、权限边界和候选比较都由Skill在后台完成。

### 3. 当天行动

默认先给结论：谁为什么付钱、买什么、什么事件才算收钱，以及本周该做什么、该停什么。

证据足够时，它会收敛到一个赚钱点和一个当前动作；证据不足时，它会给条件化候选，并只收敛到下一项最值钱的证据，不硬凑一个推荐。

默认简洁。你要比较、完整审计、顾问式访谈或先发散，直接说，它会按你要的形式展开。

说「继续」时，它只讲这一轮真正的新变化，不重印上一轮。

## 什么才算商业反馈

```text
到账 / 订金 / 订单 / 复购
> 接受价格 / 签署 / PO / 启动采购
> 决策人投入 / 提交真实资料
> 播放 / 点赞 / Star / 会议 / 客套兴趣
```

只有第一层是收钱证据，中间两层只是前进证据，最后一层不算商业结果。默认请求当下可行的最高一级。

## 怎么判断先做什么

多数情况下只推进商业链的第一个断点（下面是默认判断顺序，不是三选一的强制分支）：

```text
可联系付款方 → 问题确认 → 明确报价 → 有成本承诺 → 到账 / 复购
```

- 没有可联系的合格付款方：通常先解决触达；
- 已有目标对象、用户、旧客或询问：通常先推进成交，而不是继续做内容或功能；
- 当前动作的关键权限不清：暂停的只是那个具体动作，商业问题照答，并给出安全的核验路径。

内容只是可能的获客入口，不是默认答案；发布内容本身也不是证据。

## 原则

NIUBI Skill不保证赚钱，也不编造价格、能力、案例或客户反馈。一次付款不证明市场成立；一次失败也不能判死项目。涉及数据、IP、雇佣、平台或受监管活动时，只允许有权限、能履约的下一步。
